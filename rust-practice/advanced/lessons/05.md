# Chapter 05：借用、別名與可變性的限制

## 學習目標

由資料失效問題理解借用規則；用不重疊分割設計 safe API；理解靜態分析的保守性。

## 理論與設計理由

別名表示多個路徑指向同一份資料。只讀別名通常容易推理；當某個路徑能修改或重配資料，其他路徑可能忽然失效。例如 Vec 擴充容量可能移動元素，先前指向元素的參照不能在重配後繼續使用。這不是只有多執行緒才會發生的問題。

在基本 safe 借用模型中，&mut 提供對借用區域的獨占存取，&T 提供共享存取。實際規則還涉及重借用與內部可變性，不能解讀成「整支程式一輩子只能有一個 &mut」。需要判斷的是相關借用是否仍有效、是否可能重疊；編譯器通常可在最後一次使用後結束借用。

編譯器無法從每個任意索引計算推知兩個位置必然不同，因此即使程式設計者知道 i != j，直接連續索引可能仍被拒絕。split_at_mut 把切片安全地分成不重疊兩部分，讓這個事實出現在型別與 API 結構裡。這是「重新表達證據」，不是與編譯器比誰聰明。

two_mut 的契約必須說清楚：相同索引回傳 None，越界也回傳 None；成功時兩個回傳參照的順序對應 i、j，而不是排序後索引的順序。若忽略這項介面語意，程式可能完全沒有記憶體錯誤卻仍然算錯。safe Rust 只能排除某些類型的錯誤，無法替你保證商業規格或物理意義。

## 推理實驗

這段程式的問題不是索引超界，而是同時活躍的可變借用：

```compile_fail
let mut values = vec![10, 20];
let x = &mut values[0];
let y = &mut values[1];
*x += *y;
```

改用 split_at_mut 後，在紙上標出兩個區域的邊界。

## 實作規格

完成泛型 two_mut，不可使用 unsafe、raw pointer 或 clone 整個切片。成功時回傳原切片中兩個不同位置的可變參照，順序必須跟呼叫參數一致。

起始檔：`examples/lab05.rs`。先閱讀測試，再修改函式。

```sh
cargo test --example lab05
cargo run --example lab05
```

起始程式中的 `todo!()` 可編譯，但執行或相關測試會 panic，這是刻意保留的待完成工作；通過編譯不代表通過規格。

## 終端機自動驗收

完成作答後執行：

```sh
cargo run -- run 5
```

此命令自動編譯學生程式並執行至少十項獨立具名的函式契約檢查（清單見 `TEST_CASES.md`），不需手動輸入測試值。第十二章另有多組標準輸入／輸出與退出碼案例。驗收在暫存檔附加測試，不會修改你的程式或使用參考答案替換作答；失敗退出碼為１。起始程式中的 `todo!()` 會使驗收失敗。

需要自行輸入、觀察輸出或附加檔案路徑時，使用 `cargo run -- manual 5`；原本的 `cargo test --example lab05` 仍可執行檔案內測試。自動驗收有逾時限制，但不是執行不受信任程式的安全沙盒；有限測試也無法代替設計推理、複雜度分析與個別口頭說明。

## 驗收與設計說明

測試 i < j、i > j、i == j、空切片與越界。透過回傳的參照修改值，確認原資料相應位置被改動。額外空間 O(1)，不複製元素。

提交修改後的程式、測試結果及一頁設計說明。設計說明必須回答：不變量是什麼？錯誤如何表達？時間／額外空間成本是多少？你的測試還沒有涵蓋什麼？

## 提示

先檢查相同索引與界限，再以較大的索引分割。i > j 時，回傳左右參照的順序也要反過來。
