# Chapter 08：Trait、泛型與分派策略

## 學習目標

由需要的行為定義抽象；比較靜態與動態分派；理解抽象介面不會自動保證語意。

## 理論與設計理由

泛型函式不必知道每個具體型別的全部細節，只要求型別符合必要的 trait。這像是函式契約的另一層：需要一個 magnitude 方法，不需要繼承某個共同資料結構。Trait 描述可使用的操作，方法的數學意義仍由文件與實作遵守。

以 T: Measured 接受 &[T]，同一個切片的元素都是同一個具體 T。編譯器通常藉由單態化產生對應具體型別的版本，讓呼叫有機會被內聯與最佳化，代價可能是編譯時間與程式碼大小增加。靜態分派不是保證所有情境都比較快。

&dyn Measured 是對 trait object 的借用，可讓一個 &[&dyn Measured] 同時引用不同的具體型別。動態分派透過執行期方法表選擇實作，帶來間接呼叫與最佳化限制；&dyn 本身不要求 heap 配置，只有選擇 Box 等擁有方式時才涉及相應配置。不是所有 trait 都符合動態相容條件，例如方法含某些泛型形式會影響可用性。

本練習故意讓 Distance 與 Time 都實作 magnitude，觀察型別系統可以接受「不同物理量的數值相加」，卻不代表這是有效物理運算。Trait 合約如果只保證能取得數值，就不能推導可相加。進一步的單位型別設計要避免這種語意混淆，而非把順利編譯當成領域正確。

## 推理實驗

寫出泛型版本與 dyn 版本的資料圖，標示哪些物件借用原值、是否需要配置。解釋為什麼 &[Distance] 不能直接塞入 Time，以及 dyn 能接受它仍不代表相加有物理意義。

## 實作規格

完成 total_static 與 total_dynamic。兩者對相同量值產生相同總和；動態版本要能接受兩種實作。這是分派實驗，不是有單位的合法物理加總 API。

起始檔：`examples/lab08.rs`。先閱讀測試，再修改函式。

```sh
cargo test --example lab08
cargo run --example lab08
```

起始程式中的 `todo!()` 可編譯，但執行或相關測試會 panic，這是刻意保留的待完成工作；通過編譯不代表通過規格。

## 終端機自動驗收

完成作答後執行：

```sh
cargo run -- run 8
```

此命令自動編譯學生程式並執行至少十項獨立具名的函式契約檢查（清單見 `TEST_CASES.md`），不需手動輸入測試值。第十二章另有多組標準輸入／輸出與退出碼案例。驗收在暫存檔附加測試，不會修改你的程式或使用參考答案替換作答；失敗退出碼為１。起始程式中的 `todo!()` 會使驗收失敗。

需要自行輸入、觀察輸出或附加檔案路徑時，使用 `cargo run -- manual 8`；原本的 `cargo test --example lab08` 仍可執行檔案內測試。自動驗收有逾時限制，但不是執行不受信任程式的安全沙盒；有限測試也無法代替設計推理、複雜度分析與個別口頭說明。

泛型、動態、空集合通過。補一份設計比較，涵蓋異質集合、配置需求、程式碼大小與最佳化，並指出泛型界限沒有保證單位一致。

提交修改後的程式、測試結果及一頁設計說明。設計說明必須回答：不變量是什麼？錯誤如何表達？時間／額外空間成本是多少？你的測試還沒有涵蓋什麼？
