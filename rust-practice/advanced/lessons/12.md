# Chapter 12：整合專案：可驗證的運動資料分析器

## 學習目標

從需求建立分層架構、錯誤契約與測試計畫；整合數值限制、資料解析與終端機介面；寫出可檢閱的設計理由。

## 理論與設計理由

專案的輸入是一段 UTF-8 文字，每行恰好是「有號位移,正秒數」，沒有標題列、不接受空白行，不支援帶引號的完整 CSV。先明確限制格式，才能判定哪個輸入應成功。檔案為空與某一行格式錯誤是不同的失敗情況，錯誤需要保留原始的一起算行號。

分析核心回傳 Summary，包含筆數、總位移與總時間；平均速度是總位移／總時間。分段速度直接平均在時間不同時沒有這個意義。總路程／總時間才是平均速率，單看每筆有號位移也未必知道該段實際路程，因此本專案不冒稱計算完整路程。

每筆數值有限不保證累加結果仍有限，所以要檢查累加溢位。總位移與時間都有限也不保證最後相除為有限，例如極小正時間，因此還需要檢查最終比值。這些檢查排除非有限結果，但不消除一般浮點捨入與消去誤差；科學用途還需要誤差預算或更進一步的加總策略。

核心函式 analyze 不讀檔也不印字，CLI 負責路徑、stdin、stdout、stderr 與退出碼。當錯誤時輸出到 stderr 並回傳非零退出碼，其他程式才能以管線或自動化判斷成功與失敗。參考版本一次讀入全部文字，時間 O(n)，儲存原文為 O(n)，核心逐行累加狀態為 O(1)；它不是串流讀檔實作。

設計說明應解釋為何選擇嚴格格式、為何遇錯即停、為何保留行號，以及是否支援部分成功。這些是介面政策，不是 Rust 唯一正解。比較替代設計後，選擇與需求一致的方案，才是本課程最終要驗收的能力。

## 推理實驗

先手算兩筆 100,10 與 -40,20：總位移 60、總時間 30、平均速度 2 m/s。再建立一筆第二行格式錯誤、一筆空檔、一筆數值累加溢位。先寫出預期錯誤與退出碼，才執行。

完成後執行：

```sh
cargo run -p rust-advanced-course --example lab12 -- advanced/data/motion.csv
```

上述命令從 workspace 根目錄執行；若目前在 advanced 資料夾，路徑改成 data/motion.csv。stdin 模式先輸入各行，macOS／Linux 以 Ctrl+D 結束；Windows PowerShell／CMD 通常以 Ctrl+Z 後 Enter 結束。

```sh
cargo run -p rust-advanced-course --example lab12 -- -
```

## 實作規格

完成 analyze，保留已提供的 CLI 與測試。空檔回傳 Empty；行格式／數值錯誤回傳含行號的 Line；累加或最後比值非有限回傳 Overflow。接受 CRLF 及一般尾端換行，拒絕真正的空白資料行。

起始檔：`examples/lab12.rs`。先閱讀測試，再修改函式。

```sh
cargo test -p rust-advanced-course --example lab12
cargo run -p rust-advanced-course --example lab12
```

起始程式中的 `todo!()` 可編譯，但執行或相關測試會 panic，這是刻意保留的待完成工作；通過編譯不代表通過規格。

## 終端機自動驗收

完成作答後執行：

```sh
cargo run -p rust-advanced-course -- run 12
```

此命令自動編譯學生程式並執行至少十項獨立具名的函式契約檢查（清單見 `TEST_CASES.md`），不需手動輸入測試值。第十二章另有多組標準輸入／輸出與退出碼案例。驗收在暫存檔附加測試，不會修改你的程式或使用參考答案替換作答；失敗退出碼為１。起始程式中的 `todo!()` 會使驗收失敗。

需要自行輸入、觀察輸出或附加檔案路徑時，使用 `cargo run -p rust-advanced-course -- manual 12`；原本的 `cargo test -p rust-advanced-course --example lab12` 仍可執行檔案內測試。自動驗收有逾時限制，但不是執行不受信任程式的安全沙盒；有限測試也無法代替設計推理、複雜度分析與個別口頭說明。

## 驗收與設計說明

既有測試全過，另新增含 CRLF、負位移、缺檔與額外 CLI 參數的驗收。交付至少五個自訂測試、模組責任圖、錯誤分類表與數值限制說明。延伸重構為 lib.rs／main.rs 及 BufRead 串流版本，需證明行號與錯誤政策不變。

提交修改後的程式、測試結果及一頁設計說明。設計說明必須回答：不變量是什麼？錯誤如何表達？時間／額外空間成本是多少？你的測試還沒有涵蓋什麼？

## 提示

以 text.lines().enumerate() 保留原始行號，區分空檔與空白行。先驗證每筆，再累加，最後檢查總結與平均速度。
