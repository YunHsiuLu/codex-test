# Chapter 04：所有權、移動語意與資源生命週期

## 學習目標

區分值與儲存位置；追蹤 move 後的使用權；以 Drop 觀察資源釋放並理解 RAII。

## 理論與設計理由

記憶體模型先用來推理值的有效性，不是猜實際機器組合語言。區域變數、Box、String 與 Vec 具有不同的擁有關係；不能簡化成「所有變數一定在 stack、所有資料一定在 heap」。編譯器可以最佳化配置，語言層的所有權仍必須成立。

String 擁有字串緩衝區；把 String move 給另一個綁定後，原綁定不能再作為擁有者使用。這通常轉移對既有資源的責任，不代表深拷貝字元。clone 則建立另一個擁有的副本，對 String 可能配置與複製資料。Copy 型別可隱式複製，不能把整數與 String 的行為混為一談。

當值需要被釋放時，Rust 會執行相應的 drop 行為。這種把資源管理綁定生命週期的方式稱為 RAII，也可用於檔案與鎖，不只記憶體。擁有者可以移動，釋放責任會隨之移動；不能因為多了一個變數名稱就多釋放一次。對普通區域綁定可用詞法作用域及宣告順序追蹤，但借用有效範圍與 drop 時點不是同一件事。

本章以 Rc<RefCell<Vec<_>>> 保存事件紀錄。Rc 是單執行緒的共享所有權計數，clone Rc 會增加擁有者數量而不複製整個 Vec；RefCell 把借用衝突的檢查移到執行期，違反會 panic。它們是為了觀察實驗使用，不代表避開借用檢查就能免除規則。循環的 Rc 關係也可能讓計數無法歸零，因此 Rust 的記憶體安全不等於完全不會洩漏資源。

## 推理實驗

先解釋以下程式為何不能通過編譯，再以借用及 clone 各寫一個修正版，說明成本差異：

```compile_fail
let source = String::from("motion");
let destination = source;
println!("{source} {destination}");
```

接著在 Drop 紀錄實驗中，畫出 inner move 前後誰負責釋放。

## 實作規格

完成 scope_trace，讓事件為 enter、inner dropped、outer dropped。建立自訂 Guard 與 Drop，內層 Guard 要經過一次 move；不可手動直接拼出答案事件 Vec。

起始檔：`examples/lab04.rs`。先閱讀測試，再修改函式。

```sh
cargo test -p rust-advanced-course --example lab04
cargo run -p rust-advanced-course --example lab04
```

起始程式中的 `todo!()` 可編譯，但執行或相關測試會 panic，這是刻意保留的待完成工作；通過編譯不代表通過規格。

## 驗收與設計說明

每個 Guard 僅釋放一次，順序符合巢狀作用域。說明 clone String 與 clone Rc 的差異，以及 Drop 不能保證所有程序終止路徑都執行，例如程序直接 abort。
