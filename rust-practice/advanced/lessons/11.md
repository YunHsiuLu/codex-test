# Chapter 11：並行中的所有權與可重現結果

## 學習目標

區分資料競爭與其他競態；用作用域執行緒借用輸入；分析並行工作的成本與限制。

## 理論與設計理由

並行讓不同工作在時間上交錯或同時執行；它不會自動讓程式更快。建立執行緒、排程與等待都有成本，少量數字的加總常常由單執行緒較有效率。先確定工作可分割，再考慮資料量是否足以攤平開銷。

資料競爭涉及未同步的重疊記憶體存取，其中至少一方寫入。Rust 透過借用、Send、Sync 等機制，限制安全程式中的不安全共享。Send 描述值能否跨執行緒轉移；Sync 描述共享參照能否安全跨執行緒使用。它們不表示任意業務操作已經有正確的先後順序，也不防止死結或所有邏輯競態。

本題把輸入切成兩個共享唯讀切片，各自求和後合併。thread::scope 讓子執行緒可借用外層區域資料，並保證在作用域結束前完成等待；這與一般 thread::spawn 可能要求捕獲資料符合 'static 的情況不同。move closure 可以移動參照本身，不等於複製或取得整份底層陣列的所有權。

加總先轉成 i64，避免 i32 小範圍溢位。本練習的契約限定輸入長度不超過一百萬筆 i32，因此數學總和可由 i64 表示；不應把這個實作描述為能對任意長度永不溢位的通用函式。整數在可表示範圍內分組不改變結果；若換成浮點數，不同分組可能導致捨入差異。

Rc 不具備跨執行緒所需的執行緒安全計數；Arc 提供原子計數，但共享可變資料仍需要 Mutex、RwLock 或其他適當同步。不能只把 Rc 改名成 Arc 就宣稱整個設計安全且正確。

## 推理實驗

預測這個安全性檢查會拒絕什麼：

```compile_fail
use std::{rc::Rc, thread};
let data = Rc::new(42);
thread::spawn(move || println!("{data}"));
```

再畫出 scope 主執行緒、左半切片、右半切片與 join 的時間線。

## 實作規格

完成 parallel_sum；一個子執行緒處理左半，主執行緒處理右半，等待後合併。不得 clone 整份輸入，不需 Mutex。契約限定最多一百萬筆 i32。

起始檔：`examples/lab11.rs`。先閱讀測試，再修改函式。

```sh
cargo test --example lab11
cargo run --example lab11
```

起始程式中的 `todo!()` 可編譯，但執行或相關測試會 panic，這是刻意保留的待完成工作；通過編譯不代表通過規格。

## 終端機自動驗收

完成作答後執行：

```sh
cargo run -- run 11
```

此命令自動編譯學生程式並執行至少十項獨立具名的函式契約檢查（清單見 `TEST_CASES.md`），不需手動輸入測試值。第十二章另有多組標準輸入／輸出與退出碼案例。驗收在暫存檔附加測試，不會修改你的程式或使用參考答案替換作答；失敗退出碼為１。起始程式中的 `todo!()` 會使驗收失敗。

需要自行輸入、觀察輸出或附加檔案路徑時，使用 `cargo run -- manual 11`；原本的 `cargo test --example lab11` 仍可執行檔案內測試。自動驗收有逾時限制，但不是執行不受信任程式的安全沙盒；有限測試也無法代替設計推理、複雜度分析與個別口頭說明。

## 驗收與設計說明

空輸入、奇數長度、正負混合及超過 i32 和範圍的案例通過。論證 O(n) 總工作量，理想兩工作者約各 n／2，不能只憑理論聲稱加速。

提交修改後的程式、測試結果及一頁設計說明。設計說明必須回答：不變量是什麼？錯誤如何表達？時間／額外空間成本是多少？你的測試還沒有涵蓋什麼？

## 提示

使用 thread::scope、split_at，move closure 捕獲左半參照。join 的錯誤屬工作執行緒 panic，本題可視為內部失敗。
