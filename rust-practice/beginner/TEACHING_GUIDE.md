# 課程設計與評量指南

## 教學定位

主線以零程式背景為基準。有C++／Python經驗者可縮短熟悉內容，但仍需理解Rust不同的資料、資源與錯誤模型。教材的完整示範使用不同於作業的問題；初期提供少量框架，後期要求學生自行拆解。

## 每個主題的循環

１．先描述需求，讓學生說明輸入、輸出與不接受的情況。

２．手算少量案例，再閱讀示範，指出每個名稱的值、型別與單位。

３．追蹤狀態與呼叫，解釋結果，不能只以編譯成功當理解證據。

４．在新情境實作，逐步撤除框架。先手動探索，再跑獨立驗收。

５．根據失敗案例修正假設，另外提出未公布的案例及預期。

６．比較參考解法的選擇與限制，能口頭說明自己的程式。

教材自我檢核屬形成性評量，有答案但不假報自動通過。十筆輸入是同一程式的案例，不算十道獨立設計題。

## 題面範例數量

各題題面提供兩組公開範例，說清楚呼叫／輸入與預期回傳／輸出即可；固定輸出只有一種要求的題目可只列一組。不在題面逐一展開所有邊界與錯誤案例，其他情況由學習者依規格推演與自行設計。若附main觀察示範，只重用同兩組資料，避免另外增加已揭露案例。

資料範圍、成功／失敗條件與回傳型別仍須完整，不靠隱藏未寫出的規則增加難度。講義依需要示範不同觀念；驗收每題至少十項，完整案例目錄供維護查核，不列為作答前必讀。題面範例與自動驗收是不同階段，執行驗收後仍顯示實際結果。

## 先備回收表

| 暫借內容 | 首次使用 | 回收 |
| --- | --- | --- |
| use與單值輸入函式 | 單元２ | 單元５呼叫、單元６stdin |
| &mut input | 單元６ | 單元７可變借用 |
| 測試模組框架 | 單元５ | 單元１１測試、單元１２模組 |
| 現成Vec／Option等泛型型別 | 單元８ | 本課讀懂；自訂泛型留Advanced |

學生看不懂方法鏈時，拆成有名稱的中間值，不用更多簡寫掩蓋。

## 評量規準

建議平時實作六成，兩個專案四成，可依課堂調整，並非試教校準結果。各份評量兼看下列面向：

| 面向 | 建議比例 | 證據 |
| --- | --- | --- |
| 規格與推理 | ２５％ | 手算、追蹤、邊界、終止理由 |
| 設計與可讀性 | ２５％ | 資料與函式責任清楚、能說明借用 |
| 實作行為 | ３０％ | 正常、邊界與錯誤符合契約 |
| 測試與反思 | ２０％ | 自訂測試能抓錯、誤差合理、限制清楚 |

函式題main只供示範，不要求未被驗收的額外輸出。程式題與專案才要求完整stdout／stderr／退出碼。兩專案另交DESIGN.md與自訂測試紀錄，文件存在不等於內容合格。

第十一單元要求正確版本通過、九個故障版失敗。零測試、編譯錯誤、逾時不能當抓到錯誤；永遠失敗的測試也過不了正確版。教師應抽問案例目的，必要時加入符合契約的新故障版，避免學生只針對公開故障猜答案。

自動測試不能評估命名品質、合理分工與真正理解；不要以比對程式碼字樣假裝評估推理。

## 跨語言對照

| 常見C++／Python內容 | Rust對應 | 差異 |
| --- | --- | --- |
| cin／cout、input／print | std::io、文字緩衝、解析、輸出巨集 | 讀取、解析、領域檢查分開 |
| vector／list | Vec／切片 | 同型別元素，所有權與借用明確 |
| 修改傳入物件 | &mut T／&mut self | mut與交出借用不同 |
| 空值或錯誤代碼 | Option／Result／enum | 真正的零與沒有答案不同 |
| struct／class | struct／impl／enum／組合 | 不照搬class繼承 |
| 例外處理 | Result／match／?與panic責任區分 | ?傳遞錯誤，不忽略失敗 |
| 指標與資源清理 | 所有權、Copy／move／clone、作用域 | 入門不需raw pointer／unsafe |
| 字串索引 | UTF-8與chars | byte、scalar與人眼字元不同 |

基本遞迴列入第五單元：先追蹤不同呼叫的參數與返回，再實作階乘與最大公因數。自動驗收查結果與契約，另以程式閱讀及追蹤確認學生採用遞迴、能說明終止與成本；不靠原始碼字樣判定。更完整資料結構依原學校課綱擴充。能力對照不等於每種語言特性都一對一相同。

## 教師與維護者檢查表

- 新語法是否先解釋，或明示暫借及回收點？
- 必讀與選讀是否清楚？作業是否知道要編輯哪個檔案？
- 示範是否沒有直接交出原作業答案？是否逐步撤掉框架？
- 是否有預測、追蹤、修錯與新情境，不只有公式填空？
- 題目、答案與驗收是否使用同一契約與錯誤優先順序？
- 題面是否最多兩組公開範例，且main觀察示範重用同組資料？
- 是否適當涵蓋空資料、Unicode、EOF及數值邊界？
- 自動驗收與人工評量的界線是否清楚？
- 學生能否離開課程入口，查文件並建立自己的專案？

修改units／exercises的Markdown、curriculum.json的登錄與案例，以及獨立模板／答案。正常build不重置學生作答。維護後驗證參考解法、教材範例、刻意錯誤與文件連結；不要把答案複製覆蓋作答來測試。

設計比較來源：[Rust Book](https://doc.rust-lang.org/book/)、[CS50P](https://cs50.harvard.edu/python/)、[MIT C++課程目標](https://ocw.mit.edu/courses/6-096-introduction-to-c-january-iap-2011/pages/syllabus/)。各校範圍不同，MIT為舊課綱，不採其歷史安裝指示。尚未正式試教，需依學生表現調整節奏；所有實際驗證與限制寫入HANDOFF。
